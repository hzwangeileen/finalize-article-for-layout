# 飞书嵌入式表格自动转换规范

只要飞书文档中出现嵌入式电子表格、Sheet 卡片或 `<cite type="doc" file-type="sheets">`，执行本规范。目标是将完整的电子表格快照替换为飞书文档原生表格，同时保证失败可回滚、数据不丢失。

## 1. 前置条件

- 必须拥有飞书原文链接、文档 token，或已打开且可控的飞书页面。只有粘贴文本或截图时不能执行转换，返回 `受阻：需要飞书原文链接或可控页面`。
- 使用用户身份读写当前文档和来源表格。
- 先读取 `lark-doc` 与 `lark-sheets` Skill 的相关说明；遵守它们的全量读取、写后回读和 block ID 生命周期规则。
- 转换是内容载体迁移，不得顺便改写表格内容、调整指标口径、删行删列或重排文章结构。

## 2. 枚举来源块

1. 用文档完整读取模式获取正文、block ID 和嵌入块详情。
2. 收集所有 `<sheet token="…" sheet-id="…">` 以及 `file-type="sheets"` 的引用块，并记录：
   - 原嵌入块的 block ID；
   - 在文档中的顺序和相邻块；
   - spreadsheet token；
   - sheet ID；
   - 紧邻的表题、表注、单位和来源说明。
3. 已经是飞书文档原生 `<table>` 的块只需验证，不重复转换。

推荐的原生操作链为：`docs +fetch --detail full` → `sheets +workbook-info` → `sheets +table-get --no-header` / 分页 `+csv-get` → `sheets +sheet-info --include merges,hidden_rows,hidden_cols` → `docs +update --command block_insert_after` → 回读校验 → `docs +update --command block_delete` → 再次回读。参数和 XML 语法以当前 `lark-doc`、`lark-sheets` Skill 为准，不使用猜测的旧命令。

## 3. 读取完整源数据

对每个嵌入块分别执行：

1. 先查工作簿和子表元数据，确认 token 与 sheet ID 指向的实际子表，不猜表名。
2. 读取完整 used range，而不是当前可见区域。优先使用可跨越中间空行、空列的完整 used-range 读取；大表按连续行窗口分页，直到不存在 `has_more` 或截断。
3. 默认包含隐藏行列；另读 sheet 结构中的合并区域及隐藏行列。隐藏行列只要含有内容，就必须进入转换结果。
4. 以单元格显示值作为发布快照；不把公式文本写进文档表格。保留 `0`、空字符串和真正空单元格之间可辨认的差异，不把空单元格误删成缩短的行列。
5. 确认真实边界：表格的行数、列数、末行和末列必须来自完整 used range 与全量回读的交叉验证，不能只信 viewport、`current_region` 或工作表物理网格尺寸中的任意一个。
6. 建立源快照：二维显示值矩阵、行数、列数、合并区域、表题、表注、单位和来源。所有文本在生成文档 XML 前做 XML 转义。

## 4. 创建原生表格并安全替换

1. 在原嵌入块紧邻位置插入飞书文档原生 `<table>`，维持原文阅读顺序。
2. 用 `<thead>`、`<tbody>`、`<th>`、`<td>`、`rowspan`、`colspan` 和 `<colgroup>` 表达源结构。不要把电子表格的 A/B/C 列标和 1/2/3 行号当作业务数据写入，除非它们本来就是单元格内容。
3. 表格外的表题、单位、表注和来源若已作为独立文档块存在，则保留原块，不重复创建；若它们实际位于来源单元格中，则按原位置进入表格。
4. 不要直接删除或覆盖原嵌入块。先在相邻位置插入完整原生表格，再重新读取文档进行验证。
5. 若 API 无法读取或插入该块，改用已授权的可控飞书界面完成同样操作；仍须遵循“新表验证成功后再删旧块”的顺序。

## 5. 强制验证与提交

1. 重新读取新原生表格，比较：
   - 行数完全一致；
   - 列数完全一致；
   - 每个坐标的显示文本完全一致；
   - 合并区域一致；
   - 表题、单位、表注、来源和阅读顺序未丢失或重复。
2. 任何一项不一致时，保留原嵌入块，删除尚未通过的新表或将其留作明确标记的草稿，并返回具体差异；不得声称转换成功。
3. 只有逐格比较通过后，才删除原嵌入块。
4. 删除后再次读取相邻区域，确认原位置只剩一个已验证的原生表格，前后文顺序正确。
5. 能导出 Word 时执行一次测试导出，确认全部行列都存在、没有被截断。若当前流程要求 Word 交付但无法验证导出，则状态仍为阻塞。

## 6. 输出状态

在 `飞书表格` 中逐项报告：

- 发现的嵌入式表格数量；
- 成功转换数量；
- 行列与逐格校验结果；
- 原嵌入块是否已在校验后删除；
- Word 测试导出结果；
- 若失败，准确写出失败块、失败步骤和原数据是否仍安全保留。

未真实执行读取、插入、回读比较与替换时，不得使用“已转换”或“已通过”。
